# ACLP Agent — ایجنت سمت سیستم کاربر (نسخه 2.0.0)

برنامه پایتون کراس‌پلتفرم (ویندوز / لینوکس) که سیستم شما را به افزونه «AI Chatbot Link to PC» متصل می‌کند.

> **جدید در 2.0.0:** فرمان‌های «دروازه URL» (اصل اساسی ۵ — آدرس‌های `/url/run`) هم از همین صف عادی ایجنت اجرا می‌شوند؛ هیچ تغییری در کار با ایجنت لازم نیست — فقط نسخه را جایگزین کنید.

## نصب سریع (بدون هیچ دانلود و نصب اضافه)

1. پایتون 3.8 به بالا را نصب کنید (ویندوز: از python.org و تیک Add to PATH را بزنید). **فقط همین!**
2. این پوشه را روی سیستم خود استخراج کنید — کامل و خودکفاست.
3. اجرا کنید:
   - ویندوز: دوبار کلیک روی `start_agent.bat`
   - لینوکس: `chmod +x start_agent.sh && ./start_agent.sh`
4. در اجرای اول، آدرس سایت وردپرس و کلید API را از شما می‌پرسد و در `config.json` ذخیره می‌کند. **نکته:** در پاسخ سوال «WordPress site URL» فقط **ریشه سایت** را وارد کنید (مثل `https://example.com`)؛ نیازی به آدرس کامل `/wp-json/...` نیست — ایجنت خودش آن را اضافه می‌کند (از v1.3.1 اگر آدرس کامل چسبانده باشید، خودش اصلاحش می‌کند).

از نسخه **1.3.0** ایجنت فقط با کتابخانه استاندارد پایتون کار می‌کند: هیچ `pip install`، هیچ دانلود وابستگی و هیچ اینترنتی برای نصب لازم نیست. (`requirements.txt` فقط پیشنهادهای اختیاری مثل psutil و pyautogui دارد.)

از نسخه **2.3.0** اسکرین‌شات هم بدون هیچ وابستگی کار می‌کند: ویندوز از PowerShell داخلی خود ویندوز (System.Drawing — کل صفحه مجازی)، مک از `screencapture` و لینوکس از یکی از ابزارهای سیستمی scrot / gnome-screenshot / maim / spectacle / ImageMagick استفاده می‌کند؛ pyautogui فقط fallback اختیاری آخر است و دیگر نیازی به نصب آن نیست.

پس از اتصال، پیام `Registered as client #...` را می‌بینید؛ یعنی سیستم در پنل وردپرس (بخش «سیستم‌های متصل») ظاهر شده است.

## رفع خطای 404 ثبت‌نام (جدید در 1.3.1)

اگر در setup ایجنت به‌جای ریشه سایت، آدرس کامل REST (مثل `https://example.com/wp-json/aclp/v1` که پنل وردپرس نشان می‌دهد) را وارد می‌کردید، مسیر درخواست‌ها دوبله می‌شد و ثبت‌نام با خطای `HTTP 404: rest_no_route` رد می‌شد (گزارش تست زنده مالک). از نسخه 1.3.1 ایجنت:

- در setup هر ورودی را نرمال می‌کند و پیام `[note] Full REST endpoint detected…` می‌دهد؛
- **خودترمیمی:** اگر `config.json` قبلاً با آدرس اشتباه ذخیره شده باشد، در هر استارت اصلاح و ذخیره می‌شود (`[fix]` در لاگ) — لازم نیست دوباره setup را اجرا کنید، فقط ایجنت را استارت بزنید؛
- چک‌لیست خطای «REGISTRATION FAILED» هم بازنویسی شده است.

## زبان پیام‌های کنسول (تغییر مهم در 1.3.0)

از نسخه 1.3.0 پیام‌های ایجنت **تمام-انگلیسی** است (درخواست مالک). علت: نمایش متن فارسی در `cmd` قدیمی ویندوز قابل‌اعتماد نیست و به‌هم می‌ریخت؛ با حذف کامل متن فارسی از رابط ایجنت این مشکل برای همیشه رفع شد. خروجی خود دستورات (مثلاً خروجی یک `dir` یا محتوای فایل فارسی) بدون تغییر و به‌صورت UTF-8 منتقل می‌شود و خراب نمی‌شود.

ایجنت همچنین **مقاوم در برابر خطا** است: هر خطای مهلک چاپ می‌شود، در `aclp_agent.log` ثبت می‌شود و پنجره با «Press Enter to close» باز می‌ماند تا بتوانید علت را بخوانید (دیگر هنگام دابل‌کلیک، پنجره بی‌صدا بسته نمی‌شود).

در خطای «REGISTRATION FAILED» یک چک‌لیست ۵ مرحله‌ای رفع مشکل نمایش داده می‌شود. یادآوری: از 1.3.0 ایجنت احراز هویت را با هدر استاندارد `Authorization: Bearer` انجام می‌دهد چون بعضی هاست‌ها (مثل tpptc.ir) هدر سفارشی `X-ACLP-Key` را حذف می‌کنند.

## گفتگو با هوش مصنوعی (جدید در 1.3.0)

```bash
python aclp_agent.py chat
```

- پیام تایپ‌شده شما به هوش مصنوعی(های) متصل به کلید می‌رسد و پاسخ‌اش در همان پنجره چاپ می‌شود.
- `/file C:\path\to\file.png` — فایل را روی سایت آپلود و لینک مستقیم دانلود برای هوش مصنوعی می‌فرستد (حتی اگر پلتفرم هوش مصنوعی آپلود فایل نداشته باشد).
- `/status` وضعیت اتصال · `/help` راهنما · `/exit` خروج.
- همه پیام‌ها در پنل وردپرس (AI-PC Link ← گفتگوها) ثبت می‌شود.
- سمت هوش مصنوعی: `GET /chat/pending` + `POST /chat/reply` — جزئیات: `docs/AGENT-API.md` بخش ۱۱.

## اکشن‌های پشتیبانی‌شده در نسخه 2.0.0

| اکشن | توضیح |
|------|-------|
| `shell` | اجرای هر دستور شل (cmd/PowerShell در ویندوز، bash در لینوکس) + پرچم اختیاری `elevated:true` برای اجرای سطح بالا |
| `run_python` | اجرای کد پایتون موقت |
| `file_read` / `file_write` / `file_list` / `file_delete` / `file_mkdir` / `file_move` | عملیات کامل فایل |
| `upload_file` | ارسال فایل از سیستم به چت‌بات |
| `file_download` | دریافت فایل از چت‌بات و ذخیره روی سیستم |
| `open_url` | باز کردن مرورگر |
| `http_request` | درخواست HTTP از IP سیستم شما (وب‌گردی ایجنت) |
| `screenshot` | اسکرین‌شات — از v2.3.0 بدون هیچ وابستگی (ویندوز: PowerShell؛ مک: screencapture؛ لینوکس: scrot/gnome-screenshot/maim/spectacle/ImageMagick) |
| `sysinfo` | اطلاعات سخت‌افزار و سیستم (psutil اختیاری) |
| `process_list` / `kill_process` | مدیریت پردازه‌ها |
| `install` | نصب برنامه (winget/choco ویندوز، apt/dnf/pacman لینوکس، pip) با تلاش مجدد اختیاری با دسترسی بالا |
| `privilege_status` | گزارش وضعیت دسترسی مدیر/روت و روش‌های ممکن (اختیاری) |
| `privilege_run` | اجرای یک دستور با دسترسی مدیر/روت وقتی کاربر اعتبارها را پیکربندی کرده (اختیاری) |
| `ping` | تست اتصال |

## حالت Relay — برای چت‌بات‌های فقط-متنی

اگر چت‌بات شما نمی‌تواند کد/HTTP اجرا کند، در هر مرحله یک دستور چاپ می‌کند؛ شما آن را در ترمینال همین پوشه اجرا و خروجی JSON را به چت‌بات برمی‌گردانید:

```bash
python aclp_agent.py relay shell dir          # اجرای دستور شل (بدون نیاز به کوتیشن)
python aclp_agent.py relay sysinfo            # اکشن بدون پارامتر
python aclp_agent.py relay file_list --json {"path": "C:/Users"}   # اکشن با پارامتر
```

فرمان از همان صف عادی API رد می‌شود (تاریخچه کامل در پنل وردپرس ثبت می‌شود)، روی همین سیستم اجرا و در پایان یک بلوک JSON چاپ می‌شود. اگر config.json نباشد، اول setup اجرا می‌شود.

## دسترسی مدیر/روت (اختیاری — هیچ‌چیز اجباری نیست)
- همه اکشن‌ها با دسترسی عادی هم کار می‌کنند؛ فقط کارهای نیازمند دسترسی سطح بالا (نصب سیستمی و...) به این پیکربندی اختیاری نیاز دارند.
- در setup wizard سؤال `Configure admin elevation now?` را با Enter رد کنید = بدون ارتقا. با `y` = وارد کردن نام کاربری sudo (لینوکس) و رمز.
- یا بعداً در `config.json`:
  ```json
  {"elevation_user": "user", "elevation_password": "pass", "auto_elevate": false}
  ```
- لینوکس: `sudo -S` با رمز (و fallback به sudo ساده و `su -c`) · ویندوز: پنجره UAC ظاهر می‌شود و باید Yes بزنید.
- اگر HTTPS سایت مشکل داشت، ایجنت خودش به HTTP سوییچ می‌کند (`allow_http_fallback: false` = غیرفعال‌سازی).

## اجرای خودکار هنگام بوت (اختیاری)

**ویندوز:** کلید `Win+R` → `shell:startup` → Shortcut از `start_agent.bat` در آن پوشه بگذارید.

**لینوکس:** در crontab (`crontab -e`):
```
@reboot /path/to/agent/start_agent.sh >> /path/to/agent/boot.log 2>&1
```
