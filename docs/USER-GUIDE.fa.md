## ۱. پیش‌نیازها

**برای افزونه (سرور):**
- وردپرس 5.8 یا بالاتر
- PHP 7.4 یا بالاتر
- پیشنهاد جدی: گواهی HTTPS فعال (مثلاً رایگان با Let's Encrypt) — اما اجباری نیست؛ اگر HTTPS مشکل اشت، همه‌چیز با HTTP هم کار می‌کند (بخش ۱۲)

**برای ایجنت (سیستم شما):**
- ویندوز ۱۰/۱۱ یا لینوکس (Ubuntu/Debian/Fedora/Arch)
- پایتون 3.8 یا بالاتر — **فقط همین!** از نسخه 1.3.0 ایجنت هیچ وابستگی خارجی ندارد (فقط کتابخانه استاندارد پایتون) و هیچ pip install یا دانلودی لازم نیست؛ پوشه ایجنت کامل و خودکفاست
  - ویندوز: از [python.org](https://www.python.org/downloads/) نصب کنید و **حتماً تیک "Add Python to PATH"** را بزنید
  - لینوکس: معمولاً از قبل هست؛ وگرنه `sudo apt install python3`

## ۲. نصب افزونه وردپرس

1. از صفحه [Releases پروژه](https://github.com/Tobeseuss/ai-chatbot-link-to-pc/releases) فایل `ai-chatbot-link-to-pc-v1.3.0.zip` را دانلود کنید. **از حالت فشرده خارجش نکنید.**
2. وارد پیشخوان وردپرس شوید: **افزونه‌ها ← افزودن ← بارگذاری افزونه**
3. فایل ZIP را انتخاب، نصب و فعال کنید.
4. در منوی کناری پیشخوان، آیتم جدید **«AI-PC Link»** با آیکون لینک ظاهر می‌شود.

> نصب دستی جایگزین: پوشه را با FTP در `wp-content/plugins/` بریزید و از صفحه افزونه‌ها فعال کنید.

## ۳. ساخت کلید API

1. **AI-PC Link ← کلیدهای API**
2. در بخش «ساخت کلید جدید»:
   - **نام کلید:** یک اسم معنادار مثل «کلید چت‌بات شخصی»
   - **حداکثر سیستم‌ها:** تعداد سیستم‌هایی که مجازند با این کلید وصل شوند. `۰` یعنی نامحدود. اگر فقط یک سیستم دارید، `۱` بگذارید.
   - **یادداشت:** اختیاری
3. دکمه «ساخت کلید API» را بزنید.
4. کلید به شکل `aclp_live_...` نمایش داده می‌شود و **همیشه** در جدول همین صفحه قابل مشاهده است — دکمه «کپی» کنارش هست و هر وقت خواستید می‌توانید دوباره ببینید و کپی کنید (از نسخه ۱.۲.۰ به بعد).

نکته: کلیدهایی که قبل از نسخه ۱.۲.۰ ساخته شده بودند فقط پیشوندشان ذخیره شده؛ برای آنها یا کلید جدید بسازید یا مقدار کامل را از جایی که کپی کرده‌اید بردارید.

### جزئیات و اتصال‌های هر کلید
در جدول کلیدها روی **«📊 جزئیات و اتصال‌ها»** بزنید تا صفحه اختصاصی آن کلید باز شود:

- **کلید کامل** با دکمه کپی + وضعیت و سقف سیستم‌ها
- **استفاده دوطرفه و ترافیک:** فرمان‌های ارسالی (چت‌بات → سیستم)، نتایج دریافتی (سیستم → چت‌بات)، فایل‌های هر دو جهت + برچسب وضعیت: «دوطرفه کامل (فرمان + نتیجه + فایل)» / «دوطرفه (فرمان و نتیجه)» / «یک‌طرفه (فقط فرمان ارسالی)» / «هنوز استفاده نشده»
- **هوش مصنوعی‌ها و منابع در ارتباط:** هر AI/چت‌باتی که از این کلید فرمان صادر کرده (از ستون «منبع» فرمان‌ها)
- **سیستم‌های متصل به این کلید:** با وضعیت اتصال ایجنت (آنلاین یا ثبت‌شده-آفلاین)، سیستم‌عامل، میزبان، IP، نسخه ایجنت، **هوش مصنوعی کنترل‌کننده** (`ai_model`)، تعداد قابلیت‌ها و آخرین حضور
- **آخرین تعاملات** همان کلید
- **گفتگوی کاربر با هوش مصنوعی** (از نسخه 1.3.0): آمار پیام‌ها + ۲۰ پیام آخر رد‌وبدل‌شده از طریق حالت chat ایجنت

## ۴. نصب و اجرای ایجنت روی سیستم شما

1. از Releases فایل `aclp-agent-v1.3.0.zip` را دانلود و در یک پوشه (مثلاً `C:\ACLP` یا `~/aclp`) **استخراج** کنید. همین! هیچ نصب وابستگی لازم نیست.
2. اجرا کنید:
   - **ویندوز:** دوبار کلیک روی `start_agent.bat`
   - **لینوکس:** ترمینال را در همان پوشه باز کنید:
     ```bash
     chmod +x start_agent.sh
     ./start_agent.sh
     ```
3. اولین اجرا حالت راه‌اندازی دارد؛ سؤال‌ها را (به **انگلیسی ساده** — از نسخه 1.3.0 کنسول ایجنت تمام-انگلیسی است تا مشکل نمایش فارسی در cmd ویندوز پیش نیاید) می‌پرسد:
   - `WordPress site URL` — مثل `https://example.com` یا `http://example.com`
   - `API key` — کلیدی که در گام قبل کپی کردید
   - `Name of this computer` — مثل `my-laptop`؛ Enter بزنید تا خودش نام کامپیوتر را بگذارد
   - `Name of the AI/chatbot that will control this PC (optional)` — مثل `ChatGPT`؛ در پنل در ستون «هوش مصنوعی کنترل‌کننده» دیده می‌شود (بعداً هم با کلید `ai_model` در config.json قابل تغییر است)
   - `Configure admin elevation now? [y/N]` — **کاملاً اختیاری**؛ اگر می‌خواهید هوش مصنوعی بتواند دستورات نیازمند دسترسی مدیر/روت را هم اجرا کند `y` بزنید و مشخصات بدهید (بخش ۱۳). Enter ساده = رد کردن؛ هیچ قابلیتی از دست نمی‌دهید
4. پاسخ‌ها در فایل `config.json` کنار ایجنت ذخیره می‌شوند (این فایل محرمانه است — آن را با کسی به اشتراک نگذارید و کامیت نکنید).
5. اگر موفق باشید این پیام را می‌بینید:
   ```
   Registered as client #1 (created=True). Poll interval: 5s
   ```
6. به پنل وردپرس برگردید: **AI-PC Link ← سیستم‌های متصل** — سیستم شما باید با بج سبز «آنلاین» دیده شود. 🎉

> اگر خطایی رخ دهد، پنجره **باز می‌ماند** و دلیل خطا + چک‌لیست رفع مشکل را نشان می‌دهد (از نسخه 1.3.0)؛ جزئیات کامل هم در فایل `aclp_agent.log` کنار ایجنت ثبت می‌شود.

**توقف ایجنت:** در کنسول `Ctrl+C` بزنید.

## ۵. اتصال چت‌بات هوش مصنوعی

چت‌بات شما به یک REST API وصل می‌شود. سه چیز لازم دارد:

- آدرس پایه: `https://your-site.com/wp-json/aclp/v1`
- کلید API — ترجیحاً با هدر استاندارد `Authorization: Bearer <کلید>` (بعضی هاست‌ها هدر سفارشی `X-ACLP-Key` را حذف می‌کنند؛ Bearer همیشه می‌رسد. پلاگین هر دو را می‌پذیرد)
- مستندات کامل درخواست‌ها: [`docs/AGENT-API.md`](AGENT-API.md) — این سند را **کامل** به چت‌بات بدهید تا بخواند.

خلاصه: چت‌بات با `POST /commands` فرمان می‌فرستد و با `GET /commands/{uid}` نتیجه را می‌گیرد (یا با `wait: true` همان لحظه نتیجه را می‌گیرد).

**تست دستی بدون چت‌بات** (در ترمینال سیستم خودتان):

```bash
curl -X POST "https://your-site.com/wp-json/aclp/v1/commands" \
  -H "X-ACLP-Key: aclp_live_..." \
  -H "Content-Type: application/json" \
  -d '{"type":"sysinfo","wait":true,"timeout":15}'
```

باید اطلاعات سیستم شما در پاسخ بیاید. اگر آمد، همه‌چیز درست کار می‌کند.

### چت‌بات فقط-متنی دارید؟ (بدون قابلیت اجرای کد)
بعضی چت‌بات‌ها نمی‌توانند کد یا HTTP اجرا کنند و صرفاً متن تولید می‌کنند. برای آنها:

1. در **داشبورد پلاگین** کلید API موردنظر را از منوی کشویی بخش «نحوه اعلام نحوه استفاده از پل به ایجنت» انتخاب کنید (آدرس سایت خودکار جای‌گذاری شده) و متن را کپی و به چت‌بات بدهید.
2. چت‌بات در هر مرحله یک دستور مثل زیر چاپ می‌کند:
   ```bash
   python aclp_agent.py relay shell dir
   python aclp_agent.py relay sysinfo
   python aclp_agent.py relay file_list --json {"path": "C:/Users"}
   ```
3. شما همان دستور را در ترمینال سیستمی که ایجنت رویش اجراست کپی-اجرا می‌کنید؛ ایجنت خودش فرمان را در سرور صف می‌کند (تاریخچه کامل ثبت می‌شود)، اجرا می‌کند و یک بلوک JSON چاپ می‌کند.
4. کل خروجی JSON را کپی و به چت‌بات برگردانید تا ادامه دهد.

### گفتگوی مستقیم با هوش مصنوعی از طریق ایجنت (از نسخه 1.3.0)
می‌خواهید **خودتان** با هوش مصنوعیِ متصل به کلیدتان حرف بزنید، پیام و فایل بدهید؟ در سیستم خود این را اجرا کنید:

```bash
python aclp_agent.py chat
```

- هر متنی که تایپ کنید با Enter برای هوش مصنوعی(های) همان کلید ارسال می‌شود؛ پاسخ‌ها تا ۲ ثانیه بعد در همان پنجره چاپ می‌شوند.
- **ارسال فایل:** `/file C:\path\to\file.png` — فایل روی سایت آپلود و **لینک مستقیم دانلود** برای هوش مصنوعی ارسال می‌شود؛ حتی اگر چت‌بات شما آپلود فایل را پشتیبانی نکند، با همین لینک فایل را می‌گیرد.
- دستورات دیگر: `/status` وضعیت اتصال، `/help` راهنما، `/exit` خروج.
- سمت هوش مصنوعی: پیام‌ها را با `GET /chat/pending` می‌گیرد و با `POST /chat/reply` پاسخ می‌دهد (بخش ۱۱ سند `AGENT-API.md`).
- همه پیام‌ها و فایل‌ها در پنل **«AI-PC Link ← گفتگوها»** ثبت و قابل مرور هستند.

## ۶. کار با پنل مدیریت

### داشبورد
شش کارت آماری: کلیدهای فعال، سیستم‌های آنلاین/کل، فرمان‌های امروز، در صف، تعداد و حجم فایل‌ها. پایین صفحه ۱۵ تعامل آخر + راهنمای اتصال سریع با آدرس API آماده کپی + یادداشت پشتیبانی HTTP + بخش **«نحوه اعلام نحوه استفاده از پل به ایجنت هوش مصنوعی»** — در این بخش آدرس سایت شما **خودکار** جای‌گذاری شده، از منوی کشویی **کلید API موردنظر** را انتخاب می‌کنید تا متن بر اساس همان کلید ساخته شود و با دکمه «کپی متن آماده» برمی‌دارید (بخش ۱۴).

### کلیدهای API
- ساخت کلید جدید (بخش ۳ بالا) — کلید کامل همیشه قابل مشاهده و کپی است
- لینک **«📊 جزئیات و اتصال‌ها»** برای هر کلید (بخش ۳ بالا): سیستم‌های متصل، مشخصات ایجنت، هوش مصنوعی کنترل‌کننده و وضعیت استفاده دوطرفه
- **غیرفعال‌سازی:** کلید فوراً بی‌اثر می‌شود ولی تاریخچه‌اش می‌ماند — برای تعلیق موقت عالی است
- **حذف:** کلید + سیستم‌های متصلش + فرمان‌های در صف‌شان حذف می‌شوند (تاریخچه می‌ماند)

### سیستم‌های متصل
هر سیستم: نام، کلید متصل‌شده، سیستم‌عامل، نام میزبان، IP، وضعیت آنلاین/آفلاین، نسخه ایجنت، **هوش مصنوعی کنترل‌کننده**، تعداد فرمان‌های اجراشده، آخرین حضور. سیستم معیوب را می‌توانید حذف کنید تا ایجنت دوباره با UID جدید ثبت شود.

### تاریخچه تعاملات
- فیلتر بر اساس: جستجوی متنی (در UID و payload و نتیجه)، وضعیت، نوع فرمان
- روی **«جزئیات»** هر ردیف بزنید تا صفحه کامل باز شود: UID، همه زمان‌ها (ساخت/ارسال/پایان)، مدت اجرا، منبع فرمان، payload کامل JSON، نتیجه کامل JSON، خطاها و جدول فایل‌های منتقل‌شده با دکمه دانلود
- جهت فایل‌ها مشخص است: `⬇ چت‌بات → سیستم` یا `⬆ سیستم → چت‌بات`

### گفتگوها (از نسخه 1.3.0)
همه پیام‌ها و فایل‌های رد‌وبدل‌شده بین کاربر و هوش مصنوعی از طریق حالت chat ایجنت — با فیلتر کلید، جهت پیام (کاربر → هوش مصنوعی / هوش مصنوعی → کاربر)، فرستنده و وضعیت تحویل. لینک فایل‌ها هم قابل کلیک است.

## ۸. چند سیستم با یک کلید

- روی هر سیستم، ایجنت را جدا نصب/اجرا کنید — هر نصب خودش UID یکتا می‌سازد
- همه با همان یک کلید وصل می‌شوند و همزمان آنلاین می‌مانند
- وقتی چت‌بات بدون `client_uid` فرمان بفرستد:
  - اگر فقط یک سیستم متصل باشد → همان مقصد است
  - اگر یکی آنلاین باشد → همان انتخاب می‌شود
  - اگر چند تا آنلاین باشند → سرور لیست می‌دهد؛ چت‌بات باید `client_uid` بدهد یا `broadcast: true` بفرستد (فرمان به همه سیستم‌های آنلاین می‌رود و هر کدام نتیجه خودشان را برمی‌گردانند)
- لیست سیستم‌ها با وضعیت آنلاین: `GET /clients`

## ۹. اجرای خودکار ایجنت هنگام روشن شدن سیستم

**ویندوز (روش Startup):**
1. `Win+R` بزنید، تایپ کنید `shell:startup` و Enter
2. روی `start_agent.bat` راست‌کلیک ← **Create shortcut**
3. Shortcut را داخل پوشه باز‌شده کپی کنید

**لینوکس (cron):**
```bash
crontab -e
# این خط را اضافه کنید (مسیر را اصلاح کنید):
@reboot /home/USER/aclp/start_agent.sh >> /home/USER/aclp/boot.log 2>&1
```

**راه پیشرفته‌تر (لینوکس، سرویس systemd):** درخواست بدهید تا در نسخه بعد اضافه شود — در brainstorm.md ثبتش کنید.

## ۱۰. بروزرسانی به نسخه جدید

1. از Releases نسخه جدید **هر دو فایل** را دانلود کنید (افزونه + ایجنت — همیشه هم‌نسخه منتشر می‌شوند)
2. **افزونه:** افزونه قدیمی را غیرفعال و حذف نکنید! فقط: افزونه‌ها ← افزودن ← بارگذاری افزونه ← ZIP جدید (وردپرس خودش جایگزین می‌کند و داده‌ها می‌مانند). سپس فعال کنید.
3. **ایجنت:** ایجنت در حال اجرا را ببندید، فایل‌های جدید را روی پوشه قدیم کپی کنید **به‌جز `config.json`** (تنظیمات شما حفظ می‌شود)، دوباره اجرا کنید.
4. تغییرات هر نسخه را در [CHANGELOG.md](../CHANGELOG.md) و یادداشت‌های همان Release ببینید.

## ۱۱. عیب‌یابی کامل

### ایجنت: `[error] Python not found`
پایتون نصب نیست یا در PATH نیست. ویندوز: دوباره نصب کنید و تیک Add to PATH را بزنید، سپس یک پنجره cmd جدید باز کنید.

### ایجنت: `HTTP 401: کلید API نامعتبر است`
- کلید را دوباره از پنل کپی کنید (کلید کامل همیشه قابل مشاهده است) و در `config.json` جای‌گذاری کنید
- وضعیت کلید فعال باشد

### پنجره ایجنت بلافاصله بسته می‌شود (نسخه‌های قدیمی) — از 1.3.0 برطرف شد
از نسخه 1.3.0 پنجره در هر خطا **باز می‌ماند** و دلیل + چک‌لیست حل مشکل را نشان می‌دهد؛ جزئیات کامل هم در `aclp_agent.log` کنار ایجنت است. اگر هنوز نسخه قدیمی دارید، آپدیت کنید.
دو علت رایج که در 1.3.0 رفع شدند:
1. **هاست شما هدر سفارشی `X-ACLP-Key` را حذف می‌کرد** → ثبت‌نام همیشه 401 می‌شد؛ اکنون ایجنت از هدر استاندارد `Authorization: Bearer` استفاده می‌کند (پلاگین هر دو را می‌پذیرد)
2. **باگ ذخیره‌سازی client_uid در پلاگین** → بعد از ثبت‌نام موفق، فرمان‌ها یافت نمی‌شدند؛ در v1.3.0 پلاگین برطرف شده و هنگام آپدیت، ردیف‌های خراب قدیمی هم خودکار پاک می‌شوند — **پس بعد از آپدیت پلاگین، ایجنت را هم به 1.3.0 بروزرسانی کنید**

### ایجنت: `HTTP 404: هیچ مسیری منطبق با URL...` (rest_no_route) — از 1.3.1 برطرف شد
دو علت ممکن دارد:
1. **آدرس سایت اشتباه وارد شده بود (شایع‌ترین):** اگر به‌جای ریشه سایت (مثل `https://tpptc.ir`)، آدرس کامل REST (مثل `https://tpptc.ir/wp-json/aclp/v1` که پنل وردپرس نشان می‌دهد) را در setup ایجنت چسبانده باشید، مسیر دوبله می‌شد و همه درخواست‌ها 404 می‌خورد. **از نسخه 1.3.1 ایجنت خودش این را اصلاح می‌کند:** کافی است ایجنت جدید را استارت بزنید — `config.json` خراب به‌صورت خودکار ترمیم می‌شود و پیام `[fix]` در لاگ می‌بینید. لازم نیست دوباره setup را اجرا کنید.
2. **افزونه نصب یا فعال نیست (یا قدیمی‌تر از 1.1 است):** افزونه را از Releases نصب/فعال کنید.

### ایجنت: `HTTP 409: سقف تعداد سیستم‌ها پر شده`
در پنل، سقف کلید را بالا ببرید یا یکی از سیستم‌ها را حذف کنید.

### ایجنت: خطاهای شبکه تکراری
- سایت از دسترس خارج است؟ `https://your-site.com/wp-json/aclp/v1/ping` را با هدر کلید در مرورگر امتحان کنید
- فایروال/آنتی‌ویروس خروجی پایتون را بسته؟ اجازه دهید
- SSL error؟ اگر گواهی self-signed است آن را به سیستم اعتماد کنید یا Let's Encrypt بگیرید

### سیستم در پنل «آفلاین» است ولی ایجنت اجراست
تنظیم «آستانه آفلاین» را بیشتر کنید یا فاصله polling را کم کنید؛ اتصال سایت قطع‌ووصل دارد؟

### فرمان همیشه `pending` می‌ماند
- ایجنت در حال اجراست؟ کنسولش را ببینید
- فرمان برای سیستم دیگری از همان کلید رفته؟ (اگر چند سیستم دارید، `client_uid` را مشخص کنید)

### خطای ۴۱۳ یا شکست آپلود فایل حجیم
محدودیت PHP سرور: در `php.ini` مقادیر `post_max_size` و `upload_max_filesize` را بالا ببرید (مثلاً ۵۱۲M) و وب‌سرور (nginx: `client_max_body_size`) را هم تنظیم کنید. یا در تنظیمات پلاگین سقف حجم را کمتر کنید.

### کنسول ایجنت کاراکترهای عجیب نشان می‌دهد
از نسخه 1.3.0 پیام‌های ایجنت **تمام-انگلیسی** است و این مشکل اساساً پیش نمی‌آید (درخواست مالک: «زبان ایجنت را تماماً انگلیسی کن»). اگر خروجی یک دستور فارسی داشته باشد و درست نمایش داده نشد، در ویندوز `chcp 65001` را اجرا کنید (فایل bat خودش این کار را می‌کند) یا از Windows Terminal استفاده کنید.

### هنوز حل نشد
یک [Issue](https://github.com/Tobeseuss/ai-chatbot-link-to-pc/issues) با خروجی کنسول ایجنت (بدون کلید API!) و نسخه‌ها بسازید.

## ۱۲. پشتیبانی HTTP (وقتی HTTPS مشکل دارد)

از نسخه 1.1 سایت شما و ایجنت با هر دو پروتکل کار می‌کنند:

- **در ایجنت:** اگر آدرس را با `https://` وارد کرده باشید و اتصال HTTPS به هر دلیل (گواهی منقضی، SSL error، قطعی CDN و...) خراب شود، ایجنت به‌صورت خودکار همان درخواست را با `http://` ادامه می‌دهد و در لاگ پیام `switching base URL to: http://...` می‌نویسد. نیازی به کاری از طرف شما نیست.
- **در چت‌بات:** مسیر API روی هر دو پروتکل جواب می‌دهد؛ `GET /ping` فیلد `http_fallback_url` را هم برمی‌گرداند.
- **غیرفعال‌سازی:** اگر نمی‌خواهید ایجنت روی HTTP برود (به‌دلیل حساسیت امنیتی)، در `config.json` ایجنت `"allow_http_fallback": false` بگذارید.
- **یادآوری امنیتی:** کلید API روی HTTP قابل شنود است؛ این حالت برای «عبور از خرابی موقت HTTPS» طراحی شده، نه برای استفاده دائمی.

## ۱۳. دسترسی مدیر/روت اختیاری برای ایجنت

بعضی کارها (مثل نصب برنامه سیستمی یا تغییر تنظیمات ویندوز) به دسترسی Administrator/root نیاز دارند. از نسخه 1.1:

- **هیچ‌چیز اجباری نیست.** تمام ۲۰ اکشن ایجنت با دسترسی عادی کاربر هم اجرا می‌شوند؛ اگر کاری با دسترسی عادی انجام‌پذیر باشد، هیچ تفاوتی نمی‌کنید.
- **فعال‌سازی (اختیاری):** در setup wizard ایجنت سؤال `Configure elevation now?` را `y` بزنید، نام کاربری دارای sudo (لینوکس) و رمزش را بدهید — یا بعداً در `config.json` ایجنت این کلیدها را بگذارید:
  ```json
  {
    "elevation_user": "your-username",
    "elevation_password": "your-password",
    "auto_elevate": false
  }
  ```
- **اجرا از سمت هوش مصنوعی:** چت‌بات اول `privilege_status` را صدا می‌زند تا ببیند چه امکاناتی هست، بعد دستور سطح بالا را با `privilege_run` یا `{"type":"shell","payload":{"command":"...","elevated":true}}` می‌فرستد.
- **لینوکس:** رمز از مسیر stdin به `sudo -S` داده می‌شود؛ اگر sudo شما NOPASSWD باشد حتی بدون رمز هم کار می‌کند؛ سپس `su -c` امتحان می‌شود.
- **ویندوز:** پنجره UAC روی صفحه شما ظاهر می‌شود و باید «Yes» بزنید (بدون کلیک، اجرا با خطای شفاف شکست می‌خورد). اگر ایجنت را با Run as administrator اجرا کنید اصلاً پنجره‌ای باز نمی‌شود.
- **`auto_elevate: true`** یعنی اگر دستور عادی به‌خاطر مجوز شکست خورد، خودکار با دسترسی بالا دوباره امتحان شود. اگر آن را روشن نکنید، فقط دستورات صریحاً سطح‌بالا اجرا می‌شوند.
- امنیت: رمز در `config.json` کنار ایجنت ذخیره می‌شود (لینوکس: مجوز 0600). آن را کامیت یا به‌اشتراک نگذارید.

## ۱۴. یکپارچگی گیت‌هاب و متن آماده معرفی به ایجنت

### متن آماده «نحوه اعلام نحوه استفاده از پل به ایجنت هوش مصنوعی» (اصل اساسی ۴)
- **کجا؟** داشبورد پلاگین (با انتخاب کلید از منوی کشویی + دکمه کپی) + ابتدای README ریپو + مسیر API: `GET {آدرس سایت}/wp-json/aclp/v1/agent-prompt` (بدون نیاز به کلید؛ با `?api_key=...` کلید واقعی داخل متن جای‌گذاری می‌شود).
- **انتخاب مجزای راهنما برای هر روش (از v2.3.0):** چون راهنما با سه روش طولانی شده بود، در داشبورد منوی **«روش اتصال»** کنار منوی کلید API اضافه شد: «متن کامل» یا فقط **روش A** (چت‌بات کداجراکننده) / **روش B** (فقط-متنی) / **روش C** (دروازه URL) را انتخاب کنید تا فقط متن کوتاه همان روش — با همان کلید انتخابی — ساخته شود؛ بعد دکمه «کپی متن آماده». از API هم: `GET {آدرس سایت}/wp-json/aclp/v1/agent-prompt?method=c&api_key=کلید&format=text` — یک صفحه متنی ساده که می‌توانید مستقیم در مرورگر باز کنید و به هوش مصنوعی بدهید.
- **کلید از ابتدا در URL روش ۳ (از v2.3.0):** وقتی کلید را در داشبورد انتخاب کنید، در متن روش C همه آدرس‌ها از همان ابتدا `key=کلید` را داخل خود دارند؛ هوش مصنوعی فقط باید آدرس را باز کند و دیگر برای «گذاشتن کلید در URL» بازپرسانی نمی‌شود. متن صریحاً می‌گوید باز کردن لینک‌ها کار خودِ هوش مصنوعی است و نباید آن را به شما ارجاع دهد (رفع تجربه ChatGPT که لینک را به کاربر پس می‌داد).
- **قرارداد اجباری باز کردن URL (از v2.4.0 — درخواست مالک: «هوش‌ها URL را درست می‌سازند ولی باز نمی‌کنند»):** اگر دیدید مدل دستور را درست در URL می‌گذارد ولی لینک را باز نمی‌کند و به شما می‌گوید «خودتان باز کنید و نتیجه را بگویید»، از متن روش C نسخه **2.4.0+** استفاده کنید (داشبورد ← روش اتصال: C ← کپی). این نسخه به‌جای توصیف، یک **قرارداد مکانیکی** به مدل می‌دهد: ساختن URL فقط نیمی از درخواست است؛ درخواست فقط وقتی کامل است که مدل ① ابزار مرور وب خودش را با URL کامل واقعاً فراخوانی کند (browse / web.run / web fetch / open_url)، ② صفحه برگشتی را بخواند (نتیجه فقط همان‌جاست)، ③ در حالت pending همان RESULT URL را دوباره باز کند، ④ محتوای واقعی صفحه را به شما گزارش کند. تحویل URL به شما، «لطفاً این لینک را باز کنید»، تمام کردن کار بعد از فقط ساختن URL و حدس زدن نتیجه صراحتاً ممنوع شده و اگر ابزار مرورش خطا داد باید ۱-۲ بار تکرار و بعد پیام خطای ابزار را عیناً منتقل کند — نه اینکه نتیجه از خودش بسازد. علاوه بر متن، **خود صفحات دروازه** (ticket در انتظار، نتیجه، راهنما و خطاها) در انتهایشان به مدل یادآوری می‌دهند که گام بعدی چیست. اگر مدلی باز هم واقعاً ابزار مرور وب ندارد (نه امتناع، نداشتن ابزار)، از روش B (رله) استفاده کنید.
- **بند ضد-امتناع CAPABILITY TRUTH (از v2.5.0 — گزارش مالک: «مدل صفحه را درست باز و بررسی می‌کند ولی به‌صورت خودکار اعلام می‌کند ابزار مرور وب ندارد»):** مشاهده میدانی جدید: برخی مدل‌ها (مثلاً DeepSeek) صفحه را **درست باز و بررسی می‌کنند** ولی بلافاصله جمله‌ای از پیش‌ذخیره‌شده تکرار می‌کنند مثل «من ابزار مرور وب و باز کردن لینک‌ها را ندارم» — یعنی همان کاری که تازه انجام داده را انکار می‌کنند و کاربر فکر می‌کند کار شکست خورده. متن روش C نسخه **2.5.0+** این را با بند **CAPABILITY TRUTH** صریحاً ممنوع کرده: اگر مدل حتی یک صفحه از این سرویس را باز کرده باشد، ابزار مرور او **کار می‌کند** (هر نامی که پلتفرم بگذارد: browse / web.run / web fetch / open_url / url_reader / search) و هر جمله «نمی‌توانم لینک باز کنم» گزاره‌ای **غلط، ممنوع و نشانه شکست درخواست** است؛ تنها شکست قابل‌قبول، نقل عینی خطای واقعی ابزار پس از ۱-۲ تکرار است. قاعده مشروط مشابهی هم در Rules هر سه متن و پانویس صفحات ticket/نتیجه دروازه اضافه شده («باز کردن همین صفحه ثابت کرد ابزار مرورت کار می‌کند — هرگز نگو نمی‌توانی لینک باز کنی»). اگر مدلی باز هم بعد از باز کردن صفحه همین جمله را تکرار کرد، آن مدل را کنار بگذارید یا از روش B استفاده کنید.
- **رفع باگ اسکرین‌شات‌های تکراری (از v2.5.0 — گزارش مالک):** اگر با یک کلید API دستور اسکرین‌شات را در دو زمان مختلف اجرا می‌کردید و نتیجه شامل اسکرین‌شات‌های قبلی هم می‌شد، این یک باگ سمت سرور بود (اتصال فایل به فرمان) و در افزونه **2.5.0** رفع شد — فقط ZIP افزونه را بروز کنید؛ ایجنت و کلیدها نیازی به تغییر ندارند. (البته اسکرین‌شات‌های قدیمی که قبلاً به فرمان اشتباه وصل شده بودند در تاریخچه همان فرمان‌ها باقی می‌مانند.)
- **چیست؟** یک متن حرفه‌ای انگلیسی که به هر مدل هوش مصنوعی (حتی ضعیف‌ترین و فقط-متنی) می‌دهید تا خودش بفهمد چطور با پل کار کند. متن دو حالت دارد: **حالت A** برای چت‌بات‌هایی که کد اجرا می‌کنند (فراخوانی مستقیم API) و **حالت B** برای چت‌بات‌های فقط-متنی (دستور `aclp_agent.py relay`). جای کلید API در آن عمداً خالی است تا ایجنت از شما بپرسد — یا در داشبورد کلید را از منو انتخاب کنید تا داخل متن قرار بگیرد.
- **لحن متن (از v1.4.0 — درخواست مالک):** متن عمداً با چارچوب خنثی و حرفه‌ای «راهنمای ادغام API» نوشته شده است: مدل، سیستم را یک «سرویس پردازش کار» می‌بیند؛ کار را در ساختار JSON می‌گذارد، به URL ثبت POST می‌کند و نتیجه را پس از چند ثانیه از URL نتیجه می‌خواند. عبارت‌هایی مثل «کنترل کامپیوتر واقعی کاربر» حذف شده‌اند چون باعث می‌شد برخی مدل‌های ایمن‌آموزش‌دیده درخواست تعامل را رد کنند. توصیه: در تعریف ابزار (tool) سمت چت‌بات هم نام خنثی مثل `aclp_submit_job` انتخاب کنید، نه نام‌هایی مثل `pc_control`.
- **با هر تغییر پلاگین، این متن هم بروز می‌شود** (منبع واحد: تابع `agent_prompt` در پلاگین).
- **آدرس سایت در نسخه داشبورد همیشه خودکار جای‌گذاری شده** — چیزی برای ویرایش نیست؛ فقط کلید را انتخاب و کپی کنید.

### تنظیمات گیت‌هاب برای ایجنت‌های توسعه‌دهنده
مسیر: **AI-PC Link ← تنظیمات ← یکپارچگی گیت‌هاب**

| فیلد | توضیح |
|------|-------|
| آدرس ریپوی رسمی | پیش‌فرض: `https://github.com/Tobeseuss/ai-chatbot-link-to-pc` |
| توکن PAT گیت‌هاب | توکن با **دسترسی کامل خواندن/نوشتن** (Contents، Metadata، Actions و Administration تا جایی که گیت‌هاب اجازه می‌دهد) — همیشه قابل مشاهده است و دکمه «کپی PAT» دارد |

**این تنظیمات چه‌کار می‌کند؟** وقتی به هوش مصنوعیِ متصل به پل بگویید «قابلیت X را به برنامه اضافه کن و نسخه جدید منتشر کن»، آن ایجنت با `GET /github-integration` (با کلید API خودش) ریپو و PAT را می‌خواند و طبق `docs/AGENT-CONTRIBUTION.md`:

1. اول کامیت‌های جدید ریپو را چک می‌کند و به شما **گزارش می‌دهد** که با تغییراتش ادغام شوند یا نه
2. طبق چک‌لیست اجباری `project.md` کد + ۴ جای نسخه + همه مستندات (AGENT-API.md، README، brainstorm، worklog و...) را بروز می‌کند
3. اگر PAT مالک ریپو بود → به main پوش می‌کند و Release با دو ZIP منتشر می‌کند؛ اگر PAT شخص دیگری بود → تغییرات را به‌صورت commit در ریپوی اصلی ثبت می‌کند (یا اگر دسترسی نداشت، fork + PR)
4. در پایان به شما نسخه جدید و لینک Release را اعلام می‌کند تا پلاگین و ایجنت را بروز کنید

اگر PAT خالی باشد، ایجنت به‌جای حدس زدن، از شما می‌پرسد و شما همان توکن را در همین صفحه تنظیمات وارد می‌کنید. هرگاه توکن را عوض کردید، اینجا بروز کنید (نقشه کامل محل‌های ذخیره توکن در ریپو: `.ai/README.md` — خود توکن به ریپو commit نمی‌شود چون GitHub Push Protection آن را رد می‌کند).

## ۱۵. دروازه URL — حالت سوم تعامل (اصل اساسی ۵، از نسخه 2.0.0)

### این حالت برای چیست؟

خیلی از هوش مصنوعی‌ها و ایجنت‌ها اعلام می‌کنند «امکان تعامل با API را نداریم» ولی در همان حال می‌توانند یک آدرس وب را **باز کنند و محتوای صفحه را بخوانند** (ابزار Web Browse / باز کردن لینک). برای همین‌ها «دروازه URL» ساخته شده: **دستور در انتهای آدرس قرار می‌گیرد، آدرس باز می‌شود و نتیجه در همان صفحه به‌صورت متن ساده ظاهر می‌شود** — بدون هدر، بدون POST، بدون پارس JSON.

> پیش‌نیاز: افزونه سایت باید **نسخه 2.0.0 یا بالاتر** باشد. برای تست: آدرس `https://سایت‌شما/wp-json/aclp/v1/ping` باید `"url_gate":true` برگرداند؛ برای قابلیت کدگذاری Base64 نسخه **2.1.0+** لازم است (`"url_gate_cmd64":true`)؛ برای ping متنی و بهینه‌سازی ChatGPT نسخه **2.2.0+** (`"url_gate_ping":true`)؛ برای قرارداد اجباری باز کردن URL و یادآوری AI-facing صفحات دروازه نسخه **2.4.0+**؛ برای بند CAPABILITY TRUTH (ضد-امتناع مرور) و رفع باگ فایل‌های تکراری نسخه **2.5.0+**؛ برای متن تزریق‌ایمن و «پیام شروع» داشبورد نسخه **2.6.0+**؛ برای **کارکردن URLهای HTML-escape شده (&amp;)** و گردش «یک URL برای هر کار» (wait=20) نسخه **2.7.0+**.

### نمونه آدرس‌ها

```text
اجرای یک دستور شل (پیشنهاد از 2.7.0: با **wait=20** — نتیجه کامل معمولاً در همین صفحه اول ظاهر می‌شود و کار فقط «یک URL» می‌خواهد):

```text
https://example.com/wp-json/aclp/v1/url/run?key=aclp_live_xxxxxxxx&cmd=echo%20hello&wait=20
```

اجرای یک دستور شل با تیکت فوری (wait=0 — فقط برای کارهای بلندتر از ~۲۰ ثانیه؛ صفحه بلافاصله تیکت + URL نتیجه می‌دهد):
https://example.com/wp-json/aclp/v1/url/run?key=aclp_live_xxxxxxxx&cmd=echo%20hello&wait=0

یک کار غیر-شل (sysinfo، screenshot و...):
https://example.com/wp-json/aclp/v1/url/run?key=aclp_live_xxxxxxxx&type=sysinfo&wait=0

دستور پیچیده (کوتیشن، &، |، >، خط جدید، فارسی) — به‌صورت Base64 کدشده در cmd64 (از نسخه 2.1.0):
https://example.com/wp-json/aclp/v1/url/run?key=aclp_live_xxxxxxxx&cmd64=ZWNobyAiaGVsbG8iICYmIGxz&wait=0
(معادل echo "hello" && ls — سرور خودکار دیکد می‌کند)

تست اتصال بدون اجرای هیچ کاری — صفحه متنی انگلیسی (از نسخه 2.2.0):
https://example.com/wp-json/aclp/v1/ping?key=aclp_live_xxxxxxxx&format=text

بررسی نتیجه یک کار قبلی با شماره ticket (صفحه تا ۲۰ ثانیه منتظر می‌ماند):
https://example.com/wp-json/aclp/v1/url/result?key=aclp_live_xxxxxxxx&ticket=JOB_UID&wait=20
```

- `cmd` دستور است (فاصله‌ها `%20` و علامت `&` باید `%26` شود)؛ `wait` یعنی صفحه تا ۲۵ ثانیه منتظر نتیجه می‌ماند (پیش‌فرض ۱۵).
- **از نسخه 2.2.0 — توصیه برای ChatGPT و مشابه‌ها:** ابزار مرور این چت‌بات‌ها تایم‌اوت کوتاه دارد و `wait=15` ممکن است باعث قطع شدن کانکشن شود. با `wait=0` بفرستید (ticket فوری می‌آید) و بعد آدرس RESULT چاپ‌شده (که `&wait=20` دارد) باز کنید؛ اگر هنوز pending بود همان آدرس را هر ۵-۱۰ ثانیه دوباره باز کنید (تا ~۲ دقیقه). گزارش از این نسخه خط **NODE** هم دارد: اگر «OFFLINE» بود یعنی برنامه ایجنت روی PC اجرا نیست و باید استارت شود — تکرار بی‌فایده است.
- **از نسخه 2.4.0 — یادآوری AI-facing در خود صفحات:** همه صفحات دروازه (ticket در انتظار، نتیجه، راهنما و خطاها) در ابتدا/انتهایشان یک پانویس انگلیسی به خودِ مدل هوش مصنوعی دارند: در صفحات تمام‌شده «الان نتیجه را به زبان خودت به کاربر گزارش بده»، در صفحات pending «RESULT URL را دوباره با ابزار مرور خودت باز کن، به کاربر ارجاع نده» و در خطاها «URL را خودت اصلاح و باز کن». این پانویس‌ها بخشی از پروتکل‌اند و قرارداد متن روش C را در محل مصرف تقویت می‌کنند.
- **از نسخه 2.1.0 — قاعده مهم کدگذاری:** بعضی دستورات از نظر متنی پیچیده‌اند (کوتیشن، `&`، `|`، `>`، خط جدید، نویسه‌های غیر ASCII) و قرارگیری خام آن‌ها در آدرس URL باعث خطا و خرابی آدرس می‌شود. راه‌حل: ایجنت‌ها چنین دستوراتی را **Base64 کدشده** در پارامتر `cmd64` (مستعار `b64`) می‌فرستند و سرور خودکار دیکد می‌کند. سه شکل Base64 پذیرفته می‌شود (توصیه‌شده: URL-safe یعنی `+` به `-` و `/` به `_` و حذف `=`). JSON پیچیده کارهای پیشرفته هم از `payload64` ارسال می‌شود. اگر مقدار نامعتبر باشد، صفحه یک خطای انگلیسی واضح می‌دهد تا ایجنت کدگذاری را اصلاح و آدرس را دوباره باز کند. متن اصل ۴ (MODE C) این قاعده را به خود هوش مصنوعی‌ها آموزش می‌دهد.
- اگر کار هنوز تمام نشده باشد، صفحه یک لینک آماده «RESULT URL» چاپ می‌کند — کافی است چند ثانیه بعد آن را باز کنید.
- اگر چند سیستم به کلید متصل باشد، صفحه فهرست آن‌ها را می‌دهد؛ همان آدرس را با `&client=شناسه` دوباره باز کنید.
- فایل‌های خروجی (مثل اسکرین‌شات) به‌صورت **لینک دانلود امضاشده** در بخش FILES همان صفحه می‌آیند — در هر مرورگری باز می‌شود.

### چطور به هوش مصنوعی بدهم؟

**از نسخه 2.6.0 — دو قانون مهم تحویل (برگرفته از تجربه میدانی DeepSeek):**

1. **پیام بفرستید، نه فایل پیوست.** اگر متن راهنما را به‌صورت فایل (txt) به مدل پیوست کنید، ممکن است مدل آن را «داده غیرقابل‌اعتماد و شبه‌تزریق دستور» بداند و صریحاً از پیروی خودداری کند — این اتفاق واقعاً در آزمایش DeepSeek رخ داد و مدل حتی کلمات متهاجمی متن قدیمی (مثل FORBIDDEN و «هرگز نگو...») را به‌عنوان مدرک رد راهنما نقل کرد. متن را **به‌صورت پیام متنی داخل چت** پیست کنید.
2. **بهترین راه: «پیام شروع» داشبورد.** در داشبورد پلاگین (کارت «نحوه اعلام نحوه استفاده از پل به ایجنت هوش مصنوعی») برای هر روش و هر کلید یک **پیام کوتاه آماده** ساخته می‌شود که URL راهنما داخل آن است؛ فقط همان پیام را در چت بفرستید — مدل خودش راهنمای کامل را مستقیماً از URL باز و می‌خواند و کلید هم از قبل داخل آدرس است. این دقیقاً همان الگویی است که در آزمایش DeepSeek بلافاصله جواب داد («این آدرس را باز کن و خلاصه کن: ...»).

از نسخه 2.6.0 متن راهنما هم **تزریق‌ایمن** بازنویسی شده: به‌جای جمله‌های تحکیمی (که حس تزریق می‌ساختند)، API به‌صورت مثبت توصیف می‌شود («آدرس = درخواست، صفحه = پاسخ» + Self-check). قرارداد ۴ مرحله‌ای باز کردن URL (فراخوانی ابزار مرور ← خواندن صفحه ← تکرار RESULT URL ← گزارش به کاربر) سر جای خودش است. به‌جای ساختن دستی آدرس‌ها، پیام شروع یا متن آماده اصل ۴ (داشبورد یا بخش ابتدای README) را به مدل بدهید — بخش **MODE C** آن دقیقاً توضیح می‌دهد چطور خودش این آدرس‌ها را بسازد و نتیجه را بخواند. مستندات فنی کامل: `docs/AGENT-API.md` بخش 3.10.

### نکته امنیتی

در این حالت کلید API داخل آدرس می‌آید (لاگ سرور و تاریخچه مرورگر می‌تواند آن را نشان دهد). چون کلید از قبل هم به همان مدل‌ها داده می‌شود، این ریسک پذیرفته شده است؛ اما مثل همیشه کلید را دوره‌ای عوض کنید و کلیدهای بلااستفاده را غیرفعال کنید.
