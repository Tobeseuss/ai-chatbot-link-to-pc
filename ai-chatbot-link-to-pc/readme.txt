پل ارتباطی بین چت‌بات‌های هوش مصنوعی و سیستم‌عامل کاربر (ویندوز/لینوکس) با کلیدهای API، پشتیبانی چند سیستم همزمان و تاریخچه کامل تعاملات.

== Description ==

این افزونه یک REST API امن روی سایت وردپرسی شما ایجاد می‌کند که چت‌بات‌های هوش مصنوعی از طریق آن می‌توانند با اجرای برنامه «ایجنت» روی سیستم شما (ویندوز یا لینوکس)، فرمان اجرا کنند، فایل ببینند/ویرایش کنند، برنامه نصب کنند، فایل دانلود/آپلود کنند و مرورگر را اجرا کنند.

ویژگی‌ها:

* ساخت چند کلید API همزمان از پنل مدیریت
* اتصال چند سیستم به یک کلید با شناسه یکتا برای هر سیستم
* سه حالت تعامل برای هوش مصنوعی‌ها: REST API کامل (POST/GET)، حالت relay برای چت‌بات‌های فقط-متنی، و **دروازه URL** (اصل اساسی ۵): دستور در انتهای آدرس قرار می‌گیرد، آدرس باز می‌شود و نتیجه در همان صفحه دیده و پردازش می‌شود (`GET /url/run` و `GET /url/result`) — از نسخه 2.1.0 دستورات متنی پیچیده با **Base64 کدشده** در `cmd64` فرستاده می‌شوند تا آدرس URL خراب نشود؛ از نسخه 2.2.0 بهینه برای ChatGPT و چت‌بات‌های مرورگر: `wait=0` + خط NODE + ping متنی (`GET /ping?key=...&format=text`)؛ از نسخه 2.3.0 همه آدرس‌های این حالت از ابتدا کلید API را داخل خود دارند و راهنمای کوتاه مجزای هر روش با هر کلید از داشبورد یا `GET /agent-prompt?method=c&format=text` قابل دریافت است؛ از نسخه 2.4.0 راهنمای این حالت **قرارداد اجباری باز کردن URL** دارد (فراخوانی ابزار مرور + خواندن صفحه + گزارش به کاربر + فهرست FORBIDDEN) و صفحات دروازه هم خودشان به مدل یادآوری AI-facing می‌دهند؛ از نسخه 2.5.0 بند **CAPABILITY TRUTH** جملات خودتناقض «ابزار مرور ندارم» را از مدل‌هایی که صفحه را واقعاً باز کرده‌اند ممنوع می‌کند؛ از نسخه 2.6.0 متن‌ها **تزریق‌ایمن** بازنویسی شدند (توصیف مثبت «آدرس = درخواست، صفحه = پاسخ» به‌جای جمله‌های تحکیمی که خودشان حس تزریق می‌ساختند — تجربه میدانی DeepSeek) و **«پیام شروع» داشبورد** راهنما را مستقیماً از URL به مدل می‌رساند
* صف فرمان‌ها + دریافت نتیجه (تک‌فرمانی و همزمان با long-poll)
* انتقال فایل دوطرفه (چت‌بات به سیستم و سیستم به چت‌بات) با لینک دانلود امضاشده
* گفتگوی مستقیم کاربر با هوش مصنوعی از طریق ایجنت (`python aclp_agent.py chat`)
* تاریخچه کامل تعاملات: فرمان، نتیجه، فایل‌ها، مدت اجرا
* تنظیمات نگهداری: مدت نگهداری تاریخچه/فایل‌ها، سقف ردیف‌ها، حجم فایل
* محدودیت نرخ درخواست برای هر کلید و ذخیره‌سازی هش کلید

== Installation ==

1. پوشه افزونه را در `wp-content/plugins/` آپلود کنید و افزونه را فعال کنید.
2. از منوی «AI-PC Link → کلیدهای API» یک کلید بسازید.
3. برنامه ایجنت Python را روی سیستم خود اجرا کنید و آدرس سایت و کلید را وارد کنید.
4. راهنمای کامل: docs/USER-GUIDE.fa.md در مخزن پروژه.

== Changelog ==

= 2.6.0 =
* **بازنویسی تزریق‌ایمن متن راهنما (گزارش میدانی دوم DeepSeek):** وقتی متن راهنما به‌صورت «فایل پیوست (txt)» به مدل داده شد، مدل آن را «شبه‌تزریق دستور» برچسب زد و عین کلمات متهاجمی متن ما (CAPABILITY TRUTH / FORBIDDEN / «هرگز به کاربر نگو») را به‌عنوان مدرک رد راهنما نقل کرد؛ همان مدل با یک پیام کوتاه کاربر + URL داخل پیام بلافاصله لینک را باز کرد و نتیجه را کامل گزارش داد
* همه جمله‌های پلیس‌گونه (CAPABILITY TRUTH / FORBIDDEN / never claim / Never tell the user / must never be asked) حذف و با توصیف مثبت جایگزین شد: بخش «How a request works in this API» (آدرس = درخواست، صفحه = پاسخ) + Self-check + Accuracy notes؛ مکانیک قرارداد ۴ مرحله‌ای دست‌نخورده ماند
* **«پیام شروع» در داشبورد (توسعه اصل اساسی ۵):** پیام کوتاه آماده-کپی به‌تفکیک روش/کلید که URL راهنما (`GET /agent-prompt?method=...&format=text&key=...`) را در خود دارد — مدل خودش راهنمای کامل را مستقیماً از URL می‌خواند؛ برای روش B توضیح می‌دهد متن را به‌صورت پیام بفرستید
* **هشدار تحویل در داشبورد:** «پیام بفرستید، نه فایل پیوست» — فایل پیوست نزد مدل‌های جدید داده غیرقابل‌اعتماد محسوب می‌شود
* `/agent-prompt` حالا نام `key` را هم مثل `api_key` می‌پذیرد (نام‌های یکسان با دروازه URL)
* پانویس صفحات دروازه (ticket/نتیجه/راهنما/خطا) به لحن مثبت تغییر کرد («خواندن صفحه با ابزار مرور، همان روش صدا زدن این API است»)
* تست واحد متون راهنما به ۹۳ مورد رسید (۲۵ تست تزریق‌ایمن: حضور فریمینگ مثبت + تأیید حذف ۱۲ عبارت پرچم‌دار)

= 2.5.0 =
* **رفع باگ سمت سرور — نتیجه اسکرین‌شات شامل اسکرین‌شات‌های قبلی بود (گزارش مالک):** در `POST /agent/commands/{uid}/result` کست `(int)` روی دیکشنری `{"file_id": ...}` همیشه «۱» می‌شد و فایل شماره ۱ کلید (معمولاً اولین اسکرین‌شات) در هر نتیجه فایل‌دار بعدی دوباره به فرمان جدید وصل می‌شد؛ اکنون ارجاع‌ها نرمالایز می‌شوند (int یا دیکشنری) و فقط فایل‌های بدون فرمانِ همان کلید وصل می‌شوند — نصب ZIP افزونه 2.5.0 کافی است، ایجنت نیازی به بروزرسانی ندارد
* **بند ضد-امتناع CAPABILITY TRUTH (گزارش مالک — «مدل صفحه را درست باز و بررسی می‌کند ولی به‌صورت خودکار اعلام می‌کند ابزار مرور وب ندارد»):** متن روش C (کامل و کوتاه) حالا صریحاً می‌گوید: اگر مدل حتی یک صفحه از این سرویس را باز کرده باشد، ابزار مرور او کار می‌کند و هر جمله «I don't have web-browsing tools / I cannot open links» غلط، ممنوع و نشانه شکست درخواست است — تنها شکست قابل‌قبول، نقل عینی خطای واقعی ابزار پس از ۱-۲ تکرار است
* **قاعده مشروط در Rules هر سه متن:** «اگر صفحه‌ای از ACLP را باز کرده‌ای، هرگز نگو ابزار مرور نداری — محتوای صفحه را گزارش بده، نه disclaimer»
* **توسعه اصل اساسی ۵:** پانویس صفحات ticket و نتیجه دروازه حالا همین واقعیت را به مدل یادآوری می‌کنند («باز کردن همین صفحه ثابت کرد ابزار مرورت کار می‌کند — هرگز نگو نمی‌توانی لینک باز کنی»)
* تست واحد متون راهنما به ۸۱ مورد رسید (۱۹ تست جدید CAPABILITY TRUTH)

= 2.4.0 =
* **قرارداد اجباری باز کردن URL در روش ۳ (درخواست مالک — گزارش: «هوش‌ها دستور را درست در URL می‌گذارند ولی هیچ‌کدام آدرس را باز نمی‌کنند»):** متن راهنمای MODE C از توصیف به قرارداد مکانیکی اجباری (THE CONTRACT) تبدیل شد — توالی ۴ مرحله‌ای: ① فراخوانی واقعی ابزار مرور وب خود مدل با URL کامل (browse / web.run / web fetch / open_url)، ② خواندن صفحه برگشتی (نتیجه فقط همان‌جاست)، ③ تکرار RESULT URL در حالت pending، ④ گزارش محتوای واقعی صفحه به کاربر
* **فهرست FORBIDDEN:** تحویل URL به کاربر، عبارت «لطفاً این لینک را باز کنید»، پایان نوبت بعد از فقط ساختن URL، توصیف صفحه بدون خواندن و حدس نتیجه — همگی «درخواست ناموفق» اعلام شدند، نه جایگزین
* **پروتکل خطای ابزار مرور:** خطا/timeout ابزار → تکرار ۱-۲ بار → نقل عینی پیام خطای ابزار؛ هرگز جعل محتوای صفحه
* **چک‌لیست پایان نوبت** در قواعد اضافه شد (آیا ابزار را واقعاً فراخوانی کردی؟ صفحه را خواندی؟ مقدار واقعی نقل کردی؟)
* **توسعه اصل اساسی ۵:** صفحات خود دروازه URL پانویس یادآوری AI-facing گرفتند — صفحه ticket در انتظار، صفحه نتیجه، صفحه راهنما و صفحات خطا در انتهایشان دستور بعدی مکانیکی مدل را چاپ می‌کنند («دوباره با ابزار خودت باز کن» / «الان نتیجه را به کاربر گزارش بده» / «URL را خودت اصلاح و باز کن»)
* تست واحد متون راهنما به ۶۲ مورد رسید (قرارداد، FORBIDDEN، پروتکل خطا در هر دو متن کامل و کوتاه روش C)

* **بهینه‌سازی دروازه URL برای ChatGPT و چت‌بات‌های مرورگر (توسعه اصل اساسی ۵ — تست میدانی):** دروازه دقیقاً مثل ChatGPT تست شد و سه مانع واقعی حذف شد
* `GET /ping` حالا کلید را از پارامتر query هم می‌پذیرد (`?key=...`) و با `&format=text` یک صفحه متنی انگلیسی برمی‌گرداند (تست اتصال بدون هدر + شمارش گره‌های آنلاین)؛ `/ping` فیلد `url_gate_ping` را برمی‌گرداند

* متن pending راهنمای واقع‌بینانه می‌دهد: RESULT URL چاپ‌شده حالا `&wait=20` دارد و باید هر ۵-۱۰ ثانیه تا ~۲ دقیقه باز شود (pickup معمول ۵-۱۰ ثانیه، گره شلوغ تا ~۶۰ ثانیه)
* متن اصل ۴ (MODE C): تشخیص خودکار چت‌بات‌های مرورگر (ChatGPT/Claude/Gemini/...) + ارسال با `wait=0` (ticket فوری — بدون timeout شدن ابزار مرور) + بازیابی از خطای timeout
* ایجنت: بدون تغییر رفتار — فقط هم‌نسخه‌سازی `__VERSION__`

= 2.1.0 =
* **کدگذاری دستورات در دروازه URL (توسعه اصل اساسی ۵ — درخواست مالک):** دستورات متنی پیچیده (کوتیشن، &، |، >، خط جدید، نویسه‌های غیر ASCII) نباید خام در URL قرار بگیرند؛ پارامتر جدید `cmd64` (مستعار `b64`) دستور را به‌صورت **Base64** می‌پذیرد و سرور خودکار دیکد می‌کند
* سه شکل Base64 پذیرفته می‌شود: URL-safe (توصیه‌شده: + → - ، / → _ ، بدون پدینگ)، استاندارد خام و استاندارد percent-encoded؛ خطای دیکد با پیام انگلیسی واضح در صفحه گزارش می‌شود
* پارامتر `payload64` برای JSON پیچیده هم اضافه شد؛ `/ping` فیلد جدید `url_gate_cmd64` را برمی‌گرداند
* متن اصل ۴ (MODE C) و صفحه راهنمای دروازه URL قاعده «دستور پیچیده ⇒ Base64» را به ایجنت‌ها آموزش می‌دهند
