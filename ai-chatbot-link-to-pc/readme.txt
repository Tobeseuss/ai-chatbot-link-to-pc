پل ارتباطی بین چت‌بات‌های هوش مصنوعی و سیستم‌عامل کاربر (ویندوز/لینوکس) با کلیدهای API، پشتیبانی چند سیستم همزمان و تاریخچه کامل تعاملات.

== Description ==

این افزونه یک REST API امن روی سایت وردپرسی شما ایجاد می‌کند که چت‌بات‌های هوش مصنوعی از طریق آن می‌توانند با اجرای برنامه «ایجنت» روی سیستم شما (ویندوز یا لینوکس)، فرمان اجرا کنند، فایل ببینند/ویرایش کنند، برنامه نصب کنند، فایل دانلود/آپلود کنند و مرورگر را اجرا کنند.

ویژگی‌ها:

* ساخت چند کلید API همزمان از پنل مدیریت
* اتصال چند سیستم به یک کلید با شناسه یکتا برای هر سیستم
* سه حالت تعامل برای هوش مصنوعی‌ها: REST API کامل (POST/GET)، حالت relay برای چت‌بات‌های فقط-متنی، و **دروازه URL** (اصل اساسی ۵): دستور در انتهای آدرس قرار می‌گیرد، آدرس باز می‌شود و نتیجه در همان صفحه دیده و پردازش می‌شود (`GET /url/run` و `GET /url/result`) — از نسخه 2.1.0 دستورات متنی پیچیده با **Base64 کدشده** در `cmd64` فرستاده می‌شوند تا آدرس URL خراب نشود؛ از نسخه 2.2.0 بهینه برای ChatGPT و چت‌بات‌های مرورگر: `wait=0` + خط NODE + ping متنی (`GET /ping?key=...&format=text`)؛ از نسخه 2.3.0 همه آدرس‌های این حالت از ابتدا کلید API را داخل خود دارند و راهنمای کوتاه مجزای هر روش با هر کلید از داشبورد یا `GET /agent-prompt?method=c&format=text` قابل دریافت است؛ از نسخه 2.4.0 راهنمای این حالت **قرارداد اجباری باز کردن URL** دارد (فراخوانی ابزار مرور + خواندن صفحه + گزارش به کاربر + فهرست FORBIDDEN) و صفحات دروازه هم خودشان به مدل یادآوری AI-facing می‌دهند
* صف فرمان‌ها + دریافت نتیجه (تک‌فرمانی و همزمان با long-poll)
* انتقال فایل دوطرفه (چت‌بات به سیستم و سیستم به چت‌بات) با لینک دانلود امضاشده
* گفتگوی مستقیم کاربر با هوش مصنوعی از طریق ایجنت (`python aclp_agent.py chat`)
* تاریخچه کامل تعاملات: فرمان، نتیجه، فایل‌ها، مدت اجرا
* تنظیمات نگهداری: مدت نگهداری تاریخچه/فایل‌ها، سقف ردیف‌ها، حجم فایل
* محدودیت نرخ درخواست برای هر کلید و ذخیره‌سازی هش کلید

== Installation ==

1. پوشه افزونه را در `wp-content/plugins/` آپلود کنید و افزونه را فعال کنید.
2. از منوی «AI-PC Link → کلیدهای API» یک کلید بسازید.
3. برنامه ایجنت Python را روی سیستم خود اجرا کنید و آدرس سایت و کلید را وارد کنید.
4. راهنمای کامل: docs/USER-GUIDE.fa.md در مخزن پروژه.

== Changelog ==

= 2.4.0 =
* **قرارداد اجباری باز کردن URL در روش ۳ (درخواست مالک — گزارش: «هوش‌ها دستور را درست در URL می‌گذارند ولی هیچ‌کدام آدرس را باز نمی‌کنند»):** متن راهنمای MODE C از توصیف به قرارداد مکانیکی اجباری (THE CONTRACT) تبدیل شد — توالی ۴ مرحله‌ای: ① فراخوانی واقعی ابزار مرور وب خود مدل با URL کامل (browse / web.run / web fetch / open_url)، ② خواندن صفحه برگشتی (نتیجه فقط همان‌جاست)، ③ تکرار RESULT URL در حالت pending، ④ گزارش محتوای واقعی صفحه به کاربر
* **فهرست FORBIDDEN:** تحویل URL به کاربر، عبارت «لطفاً این لینک را باز کنید»، پایان نوبت بعد از فقط ساختن URL، توصیف صفحه بدون خواندن و حدس نتیجه — همگی «درخواست ناموفق» اعلام شدند، نه جایگزین
* **پروتکل خطای ابزار مرور:** خطا/timeout ابزار → تکرار ۱-۲ بار → نقل عینی پیام خطای ابزار؛ هرگز جعل محتوای صفحه
* **چک‌لیست پایان نوبت** در قواعد اضافه شد (آیا ابزار را واقعاً فراخوانی کردی؟ صفحه را خواندی؟ مقدار واقعی نقل کردی؟)
* **توسعه اصل اساسی ۵:** صفحات خود دروازه URL پانویس یادآوری AI-facing گرفتند — صفحه ticket در انتظار، صفحه نتیجه، صفحه راهنما و صفحات خطا در انتهایشان دستور بعدی مکانیکی مدل را چاپ می‌کنند («دوباره با ابزار خودت باز کن» / «الان نتیجه را به کاربر گزارش بده» / «URL را خودت اصلاح و باز کن»)
* تست واحد متون راهنما به ۶۲ مورد رسید (قرارداد، FORBIDDEN، پروتکل خطا در هر دو متن کامل و کوتاه روش C)

= 2.3.0 =
* **راهنمای مجزا برای هر روش (درخواست مالک):** راهنمای اتصال طولانی شده بود؛ حالا در داشبورد پلاگین منوی «روش اتصال» کنار منوی کلید API است و می‌توانید فقط متن کوتاه همان روش (کامل / A / B / C) را با هر کلید بسازید و کپی کنید
* `GET /agent-prompt` پارامترهای جدید `method=a|b|c` و `format=text` دارد — خودِ توزیع راهنما هم از طریق «باز کردن URL» ممکن شد (توسعه اصل اساسی ۵)
* **کلید API از ابتدا در URL روش ۳ (درخواست مالک):** همه آدرس‌های MODE C از همان ابتدا `key=...` را داخل خود دارند؛ از هوش مصنوعی خواسته نمی‌شود کلید را در URL بگذارد؛ متن صریحاً می‌گوید باز کردن لینک‌ها کار خود ایجنت است و نباید لینک را به کاربر پس دهد (رفع گزارش واقعی ChatGPT)
* **اسکرین‌شات بدون هیچ وابستگی (درخواست مالک):** اکشن `screenshot` ایجنت دیگر pyautogui نمی‌خواهد — ویندوز با PowerShell داخلی خودش (System.Drawing، کل صفحه مجازی)، مک با `screencapture` و لینوکس با scrot/gnome-screenshot/maim/spectacle/ImageMagick؛ pyautogui فقط fallback اختیاری ماند
* ایجنت 2.3.0: فقط همین تغییر (اسکرین‌شات) — جایگزینی فایل aclp_agent.py کافی است، setup لازم نیست
* تست واحد ۳۷ موردی جدید برای متون راهنما (`scripts/test_prompt_modes.php`)

= 2.2.0 =
* **بهینه‌سازی دروازه URL برای ChatGPT و چت‌بات‌های مرورگر (توسعه اصل اساسی ۵ — تست میدانی):** دروازه دقیقاً مثل ChatGPT تست شد و سه مانع واقعی حذف شد
* `GET /ping` حالا کلید را از پارامتر query هم می‌پذیرد (`?key=...`) و با `&format=text` یک صفحه متنی انگلیسی برمی‌گرداند (تست اتصال بدون هدر + شمارش گره‌های آنلاین)؛ `/ping` فیلد `url_gate_ping` را برمی‌گرداند
* گزارش دروازه خط **NODE** دارد: نام گره مقصد، آنلاین/آفلاین و سن ضربان — اگر گره آفلاین باشد ایجنت فوراً می‌فهمد تکرار بی‌فایده است
* متن pending راهنمای واقع‌بینانه می‌دهد: RESULT URL چاپ‌شده حالا `&wait=20` دارد و باید هر ۵-۱۰ ثانیه تا ~۲ دقیقه باز شود (pickup معمول ۵-۱۰ ثانیه، گره شلوغ تا ~۶۰ ثانیه)
* متن اصل ۴ (MODE C): تشخیص خودکار چت‌بات‌های مرورگر (ChatGPT/Claude/Gemini/...) + ارسال با `wait=0` (ticket فوری — بدون timeout شدن ابزار مرور) + بازیابی از خطای timeout
* ایجنت: بدون تغییر رفتار — فقط هم‌نسخه‌سازی `__VERSION__`

= 2.1.0 =
* **کدگذاری دستورات در دروازه URL (توسعه اصل اساسی ۵ — درخواست مالک):** دستورات متنی پیچیده (کوتیشن، &، |، >، خط جدید، نویسه‌های غیر ASCII) نباید خام در URL قرار بگیرند؛ پارامتر جدید `cmd64` (مستعار `b64`) دستور را به‌صورت **Base64** می‌پذیرد و سرور خودکار دیکد می‌کند
* سه شکل Base64 پذیرفته می‌شود: URL-safe (توصیه‌شده: + → - ، / → _ ، بدون پدینگ)، استاندارد خام و استاندارد percent-encoded؛ خطای دیکد با پیام انگلیسی واضح در صفحه گزارش می‌شود
* پارامتر `payload64` برای JSON پیچیده هم اضافه شد؛ `/ping` فیلد جدید `url_gate_cmd64` را برمی‌گرداند
* متن اصل ۴ (MODE C) و صفحه راهنمای دروازه URL قاعده «دستور پیچیده ⇒ Base64» را به ایجنت‌ها آموزش می‌دهند
